## 第三轮：修复「下载中保存目录看不到文件」（同日 11:20 后）
- 现象：界面显示已下载若干分片，但 `%USERPROFILE%/Downloads` 无文件。根因：分片只写临时目录 `%TEMP%/M3u8Downloader/<hash>/NNNNNN.seg`，全部分片完成并 `MergeAsync` 后才生成最终文件。另有两处误导：未装 ffmpeg 时后缀由 .mp4 降为 .ts 但界面仍显示 .mp4；保存目录不存在时「目录」按钮静默失效。
- 改进：`DownloadJob` 新增可见实时输出 `<stem>.ts`，分片按序实时追加，合并阶段若已全量追加则复用，否则回退从分片重建；断点续传每次 Start 按临时目录已有分片重建可见文件（不用 state 文件，规避暂停写入竞态）。
- 关键坑：长期持有 `FileShare.Read` 的写句柄会让 `File.ReadAllText` / 播放器打不开文件（Windows 共享是双向校验，实测 IOException）。改为每批写入后立即释放句柄，写完文件随时可读。
- 顺手修 `_completed` 断点续传重复计数（启动前统计已有 `.seg`，已存在分片不再 +1）；ffmpeg 转封装失败时输出改为 .ts 而非错扩展名的 .mp4。
- 界面：卡片显示 `DisplayFileName`（完成后为实际文件名）、`LocationText` 完整路径行、「位置」（explorer /select 选中文件 + 自动创建目录）、「缓存」（打开临时分片目录）；`MainViewModel` 添加任务时校验并创建保存目录，`UniqueFileName` 同时避让同名 .ts。
- 验证：0 警告 0 错误；端到端测试扩为 15 组，新增「下载中可见 TS 文件存在 / 按序追加 / 最终内容一致」全部通过；GUI 启动 6s 无异常输出。新 exe 已写入默认 bin，但需用户重启应用生效。

## 第四轮：A+B 合并（任务目录隔离 + 缓存自动清理）（同日 11:46 后）
- 用户确认：A/B 合并 = B 管「运行时不产生垃圾」（分片即用即删）+ A 管「异常残留兜底清理/续传保守降级」；任务文件夹用任务名，重名加 `_yyyyMMdd`（同日再重名 `_2`）。缓存默认外置 `%LOCALAPPDATA%`（用户未反对推荐值）。
- 新增 `Services/TaskPaths.cs`：成品 `<保存目录>/<任务名>/<文件名>`；缓存 `%LOCALAPPDATA%/m3u8downloader/cache/<urlHash16>`（`task.path` marker + `resume.state`/`live.state`）；同 URL 有未完成状态时复用任务文件夹续传，否则分配新文件夹（重名加日期）。
- 清理：`CleanupStale(maxAge, protected, roots)` 只删缓存根目录下「16 位 hex 名 + 程序标记/分片/空目录」的目录，绝不动保存目录；`CacheSize()` 统计。启动立即清旧版 `%TEMP%/M3u8Downloader`（新版不再使用），新版 cache 只清 24h 前孤立目录；设置区显示占用 + 一键清理（排除活动任务）；移除任务只清缓存、保留成品。
- 引擎改为状态驱动续传：`resume.state` = `fingerprint|nextIndex|bytesWritten|initWritten`；数据落盘后原子写 state，启动时按 bytesWritten 截断输出文件、从 nextIndex 继续；指纹不匹配/文件丢失则保守从头重下。分片写入输出后立即删除，缓存只留乱序未完成分片；写入失败保留分片，合并阶段兜底按序补齐（保留 A 的降级能力）。
- `MergeAsync` 不再从 0 重建 `.merging`，改为补齐尾部分片后直接以实时 TS 作为 ffmpeg 输入；ffmpeg 失败时输出改为 .ts；直播状态移到 `TaskPaths.LiveStatePath`；「位置」打开任务文件夹。
- 验证：0 警告 0 错误；端到端测试扩到 19 组，新增任务目录隔离 / 缓存即用即删与完成后清空 / 崩溃后按 state 截断续传 / 清理安全边界（不删非程序目录与成品）；GUI 启动 6s 无异常；旧版 `%TEMP%` 残留已在启动时清空。
- 已知边界：移除未完成任务会留下含半成品 .ts 的任务文件夹（成品保留策略），需手动删；旧版缓存分片不迁移，重跑旧链接需重新下载。
